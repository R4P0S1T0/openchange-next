# M2b: NSPI over MAPI/HTTP so Outlook resolves names and lists the GAL — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Outlook's address book requests on `/mapi/nspi/` succeed: the profile opens without the ~90 s NSPI wait, "Address Book" lists every active PostfixAdmin mailbox, and typing a name or address in To: resolves it.

**Architecture:** NSPI is implemented in the Rust daemon (new `mapihttpd/src/nspi/`), not through the C `emsabp`. `openchange_directory_sync` writes, next to `directory.ldb`, a plain snapshot `directory.tsv` (one active mailbox per line: lower-case address, TAB, display name). The daemon loads it at start and reloads it when its mtime changes. Every identity value (nickname, LegacyDN) comes from the same functions Autodiscover and the C directory already use, so EMSMDB, Autodiscover and NSPI agree. A Bind creates a session in the existing `SessionTable` (same cookie rules as Connect); Minimal Entry IDs (MIds) are the snapshot's row index + `0x10`, stable for one snapshot.

**Tech Stack:** Rust 1.85, existing crate dependencies only (no serde); Python 3 (`python/openchange/directory.py`); fixtures captured from Outlook 16.0.19127 in the lab.

**Spec:** `doc/MODERNIZATION.md` (Roadmap M2: "Outlook creates the profile and the GAL lists users"; M2c lab result: NSPI is Bind-only and Outlook waits about 90 s), `docs/plans/2026-11-03-m2a-directory-connect.md` (M2b scope line), MS-OXCMAPIHTTP 2.2.5 (NSPI request/response bodies), MS-OXNSPI (semantics, STAT, MIds, property set), MS-OXOABK (address book object properties).

## Decisions

1. **Rust, not `emsabp`.** `emsabp` needs SamDB features (`samdb_ntds_objectGUID`, AD attribute schema, VLV controls) that the plain directory LDB does not have, and the MAPI/HTTP NSPI bodies are not the NDR structures `dcesrv_exchange_nsp.c` decodes, so a C boundary would mean a new hand-written parser of untrusted input in C anyway. The GAL here is "every active mailbox, one container", small enough to serve from memory. This replaces the M2a plan's "C boundary over emsabp" line. Cost if wrong: features `emsabp` already has (display templates, distribution lists) must be written again in Rust when they are needed.
2. **Snapshot, not LDB, for Rust.** The sync already reads PostfixAdmin; writing a second, trivially parsed file beside the LDB, in the same atomic temp-file + rename, keeps one source and needs no LDB reader in Rust. Lines with a TAB or newline inside a field cannot occur: the writer replaces them with spaces.
3. **One container.** GetSpecialTable returns a single GAL row (container MId 0, `PidTagDisplayName` "Global Address List"; MS-OXNSPI 3.1.4.1.3). No address lists, no distribution lists, no hidden entries in M2b.
4. **Order:** the GAL table is sorted by display name, case-insensitive, then by address (SortTypeDisplayName). MId = 0x10 + index; MIds from an older snapshot that no longer exist answer `MAPI_E_NOT_FOUND`/`ErrorCode` per request, never another user.
5. **Property set served** (MS-OXOABK 2.2): `PidTagDisplayName`, `PidTagAddressBookDisplayNamePrintable`, `PidTagEmailAddress` (LegacyDN), `PidTagAddressType` ("EX"), `PidTagSmtpAddress`, `PidTagAccount` (nickname), `PidTagObjectType` (MAILUSER 6), `PidTagDisplayType` (DT_MAILUSER 0), `PidTagDisplayTypeEx`, `PidTagEntryId` (permanent EntryID: flags 0, provider UID GUID `DCA740C8-C042-101A-B4B9-08002B2FE182`, version 1, display type, LegacyDN NUL-terminated), `PidTagInstanceKey`/`PidTagRecordKey` (4-byte MId / EntryID), `PidTagSearchKey` ("EX:" + upper-case LegacyDN + NUL), `PidTagProxyAddresses` ("SMTP:" + address), `PidTagTransmittableDisplayName`, `PidTagMappingSignature`. Any other requested tag comes back as `PtypErrorCode` `MAPI_E_NOT_FOUND` in that column (row flag 0x1).
6. **Strings:** PtypString8 values in the code page of the STAT; anything not representable is sent as PtypString (UTF-16LE) only when the client asked for the Unicode tag. Requests whose STAT code page is not 1252, 65001 or 20127 still work; non-ASCII becomes `?` in 8-bit strings (shortcut, documented in code).
7. **ResolveNames / GetMatches matching:** ambiguous name resolution (MS-OXNSPI 3.1.4.7) over address, local part, nickname and display-name words, case-insensitive prefix match. One match → MId, none → `MID_UNRESOLVED` (0), several → `MID_AMBIGUOUS` (1). GetMatches supports the restriction Outlook's "Search" sends (property restriction / content restriction on `PidTagAnr` or display name); any other restriction answers `ecTooComplex`.
8. **No log of names, addresses or search strings.** The trace logs request type, element counts and result codes only.

## Global Constraints

- Debian 13 packages only; no new crate, no new Python package.
- No AD, no LDAP server, no Samba daemon.
- Never log passwords, Authorization, cookies, names, addresses or search strings.
- All parsing of request bodies is bounds-checked; a short or malformed body answers `X-ResponseCode` 6 (invalid request body), never a panic. `#![deny(unsafe_code)]` stays.
- Lab VM only (lab.fitasonline.com.br); never the production mail server.
- Work on branch `m2b` from `m2c`; English commits with the Co-Authored-By trailer; push to the fork after green local checks. M2 (m2a + m2c + m2b) merges to main after this plan's final review.

## Review Focus

1. **Truncated and hostile bodies** for every request type (counts larger than the body, nested restrictions deeper than 8, strings without NUL): reply code 6, no panic, no allocation proportional to a claimed count. Pinned by a truncation loop per request type (as `test_connect_capture_truncated`), Task 1 and each request task.
2. **Snapshot reload while a client pages a table:** a MId from the old snapshot never returns another user's row. Pinned by `test_stale_mid_after_reload` (Task 2).
3. **A mailbox deactivated in PostfixAdmin** disappears from the GAL within one sync cycle and its MId stops resolving. Pinned by `test_inactive_not_in_snapshot` (Task 2) and `test_stale_mid_after_reload`.
4. **Session isolation:** an NSPI cookie is never accepted on `/mapi/emsmdb/` and vice versa; a Bind cookie bound to user A is rejected for user B's credentials. Pinned by `test_nspi_cookie_not_emsmdb` (Task 1).
5. **Non-ASCII display names** ("José Ünal") round-trip in Unicode columns and degrade to `?` only in 8-bit columns. Pinned by `test_unicode_display_name` (Task 3).
