# M3: read-only IMAP mapistore backend so Outlook shows the Dovecot mailbox — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Outlook shows the user's real Dovecot folders (Inbox, Sent, Drafts, Trash, Junk and every folder created in webmail, with subfolders) and their messages: list, open, read body (text/HTML) and attachments. Nothing is written to IMAP in M3.

**Architecture:** A new mapistore backend `mapistore_imap.so` (C, libetpan), loaded by `mapistore_backend_init` from `$(libdir)/mapistore_backends`, namespace `imap://`. It logs in to Dovecot on 127.0.0.1 as `<user>*openchange` (Dovecot master user, password from a 0600 file named in smb.conf) and opens folders with EXAMINE (read-only). `list_contexts` offers Inbox (MAPISTORE_MAIL_ROLE), Drafts, Sent and Trash (by SPECIAL-USE) as main folders, which takes over the native M2c folders with their folder IDs, and every other top-level IMAP folder as a secondary mail entry. Subfolders come from the folder's hierarchy table. Folder and message IDs are allocated through the mapistore indexing context and keyed by URI: `imap://<user>/<mailbox>/` for folders and `imap://<user>/<mailbox>/<uidvalidity>/<uid>` for messages, so a UIDVALIDITY change yields new message IDs, never another message.

**Tech Stack:** C, libetpan 1.9.4 (Debian 13 `libetpan-dev`), Dovecot 2.4 (lab, and `dovecot-imapd` for tests), existing mapistore/EMSMDB code, the oc_emsmdb smoke harness.

**Spec:** `doc/MODERNIZATION.md` roadmap M3 ("read-only IMAP backend: Outlook shows Dovecot folders and mail"), maintainer decisions of 2026-11-03: Dovecot master user `openchange` restricted to 127.0.0.1 with its password in a 0600 file; libetpan as the IMAP/MIME library; backend in C (option A, chosen over a revived Python bridge). MS-OXCMSG/MS-OXOMSG/MS-OXCFOLD for the properties served; RFC 9051 (IMAP4rev2), RFC 6154 (SPECIAL-USE), RFC 5322/2045-2049 (messages, MIME).

## Decisions

1. **Read-only.** EXAMINE only; every write entry point (create/delete/move folder or message, set_properties on IMAP objects, set_read_flag, save, submit) answers `MAPISTORE_ERR_NO_ACCESS`; Outlook keeps local state where it can. Writes are M4.
2. **One IMAP connection per mapistore context user**, opened lazily, reused across ROPs of that session, closed with the context. Reconnect once on a dropped connection; a second failure answers `MAPISTORE_ERR_NOT_FOUND` for that call.
3. **Authentication:** `LOGIN <user>*openchange <password>` (Dovecot master user syntax, `auth_master_user_separator = *`). The password file path is `mapistore:imap_master_password_file`; read once at init, never logged. Host/port from `mapistore:imap_host` (default 127.0.0.1) and `mapistore:imap_port` (143); plaintext LOGIN only to a loopback address, otherwise STARTTLS is required.
4. **Folder mapping:** INBOX → MAIL main; `\Drafts` → DRAFTS main; `\Sent` → SENTITEMS main; `\Trash` → DELETEDITEMS main; all other top-level mailboxes (including `\Junk`) → MAIL secondary (`main_folder = false`). Outbox stays native. IMAP names are modified UTF-7 (RFC 3501 5.1.3): decoded for PidTagDisplayName, kept encoded in URIs (percent-encoded for `/` and `%`).
5. **Message properties (message table and open message):** PidTagSubject/NormalizedSubject, PidTagSenderName/EmailAddress/SmtpAddress (From), PidTagSentRepresenting* (same), PidTagDisplayTo/Cc, PidTagMessageDeliveryTime (INTERNALDATE), PidTagClientSubmitTime (Date:), PidTagMessageSize (RFC822.SIZE), PidTagMessageFlags (MSGFLAG_READ from `\Seen`, MSGFLAG_HASATTACH from BODYSTRUCTURE), PidTagMessageClass `IPM.Note`, PidTagInternetMessageId, PidTagImportance, PidTagHasAttachments, PidTagIconIndex, PidTagLastModificationTime, PidTagMid/PidTagFolderId (from indexing). Opened messages add PidTagBody (text/plain, or text from HTML), PidTagHtml (text/html), PidTagTransportMessageHeaders, recipients (To/Cc/Bcc, SMTP address type) and an attachment table (PidTagAttachFilename/LongFilename, PidTagAttachMimeTag, PidTagAttachSize, PidTagAttachDataBinary, PidTagAttachMethod ATTACH_BY_VALUE). Charsets are converted to UTF-8 by libetpan's charconv; undecodable bytes become U+FFFD.
6. **Folder properties:** PidTagDisplayName, PidTagContainerClass `IPF.Note`, PidTagContentCount (EXISTS), PidTagContentUnreadCount (STATUS UNSEEN), PidTagSubfolders, PidTagFolderType, PidTagFolderId/ParentFolderId.
7. **Caching:** a folder's UID list and the fetched envelope/flags/size are cached per context and refreshed when the folder is reopened (STATUS UIDNEXT/MESSAGES/HIGHESTMODSEQ change). Message bodies are fetched on open only (BODY.PEEK[], capped at 32 MiB per message; larger messages show headers and a body notice).
8. **No new logs of content:** the trace logs folder counts and IMAP response codes only; never subjects, addresses, bodies or the master password.

## Global Constraints

- Debian 13 packages only; the only new dependency is `libetpan-dev`/`libetpan20` (approved 2026-11-03). Tests may use `dovecot-imapd` from Debian.
- No AD, no LDAP server, no Samba daemon.
- Never log passwords, Authorization, cookies, message content, subjects or addresses.
- Every IMAP-derived length/count is bounds-checked; malformed server responses fail the call, never crash. ASan/UBSan clean on the backend tests.
- Lab VM only (lab.fitasonline.com.br); never the production mail server (192.168.0.227).
- Branch `m3` from `main`; English commits with the Co-Authored-By trailer; push to the fork after green checks; merge at milestone close after the final review.

## Review Focus

1. **Hostile or odd mailbox names** (`/`, `%`, `"`, non-ASCII, `INBOX.Sub` vs `INBOX/Sub` hierarchy separators, very deep trees): URIs stay unique and reversible, display names decode, no crash. Pinned by `test_mailbox_name_round_trip` (Task 2).
2. **UIDVALIDITY change or a message expunged in webmail while Outlook has the folder open:** stale MIDs answer NOT_FOUND, never another message. Pinned by `test_uidvalidity_change_new_mids` (Task 3).
3. **Malformed MIME** (missing boundary, bad charset, nested message/rfc822, huge headers): the message opens with what can be decoded, never a crash or unbounded allocation. Pinned by `test_malformed_mime_opens` (Task 4).
4. **Dovecot down or master password wrong:** logon still succeeds with native folders unchanged (no folder deleted from openchangedb because the backend listed nothing). Pinned by `test_imap_down_keeps_folders` (Task 2).
5. **A different user's mailbox:** the backend only ever logs in as the session's own user (`username` of the context, never a name from a URI). Pinned by `test_uri_user_must_match` (Task 2).
