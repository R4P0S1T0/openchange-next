# Stage B — Outlook server rules as Sieve — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen 2026-11-13) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Ponytail full.

**Goal:** Outlook server rules on the Inbox are stored in a per-user Sieve script `outlook` and run by Dovecot at delivery; Outlook reads them back as enabled (or `ST_ERROR` when not translatable).

**Architecture:** Mirror the existing permissions path: a new mapistore folder op `modify_rules` (like `modify_permissions`) and `MAPISTORE_RULE_TABLE` served by the backend's `open_table` (like `MAPISTORE_PERMISSIONS_TABLE`). The IMAP backend keeps the rules only inside `~/sieve/outlook.sieve`, written and read through ManageSieve as the master user.

**Tech Stack:** C, libetpan `mailstream`, Samba NDR/talloc/`base64_*_data_blob`, Dovecot 2.4 Pigeonhole (ManageSieve, `sievec`, `sieve-test`), the existing `imap-backend-test` libcheck-free harness.

**Spec:** `docs/superpowers/specs/2026-11-13-stage-b-outlook-rules-sieve-design.md`

## Global Constraints

- Work on branch `stage-b` in worktree `.build/worktrees/stage-b`; no push/merge without the user's word.
- Script name `outlook`, never `SETACTIVE`; never read, write or delete any other script.
- Settings: `mapistore:sieve_host` (default `127.0.0.1`, loopback only), `mapistore:sieve_port` (default `4190`), `mapistore:sieve_tunnel` (tests, PREAUTH stdio, no TLS). Same master user/password as IMAP; login `<user>*<master>` exactly as `imap_smtp_send`.
- STARTTLS is mandatory unless the tunnel is used.
- Script header line exactly `# openchange-rules v1 -- generated by OpenChange; edits are overwritten`; rule lines `# rule <base64 of NDR mapi_SPropValue_array>`.
- Only the Inbox context implements rules; everything else returns `MAPISTORE_ERR_NOT_IMPLEMENTED` and emsmdb keeps today's stub.
- `ST_ERROR` (0x02) is computed at generation time, never trusted from the client. `ST_ENABLED` = 0x01, `ST_EXIT_LEVEL` = 0x10.
- Strings put in Sieve: escape `\` and `"`; any CR, LF or NUL → rule is `ST_ERROR`.
- `OP_DELETE` and move to Deleted Items both → `fileinto` the Trash mailbox.

## Review Focus

1. A rule whose subject/sender text contains `"`, `\` or a newline — must not break out of the Sieve string (Task 2 test `test_sieve_escape`).
2. `ROW_MODIFY`/`ROW_REMOVE` of an unknown `PidTagRuleId` — `MAPI_E_NOT_FOUND`, script unchanged (Task 3 test `test_rules_unknown_id`).
3. ManageSieve down or `PUTSCRIPT` refused — Outlook gets `MAPI_E_CALL_FAILED`, the previous script stays (Task 3 test `test_rules_put_refused`).
4. A script edited by hand or truncated — unknown lines are ignored, a corrupt `# rule` line is skipped with a level-1 log, never a crash (Task 2 test `test_rules_decode_garbage`).
5. User with SOGo filters — `outlook` never touches `sogo` and delivery without `outlook.sieve` is normal (Task 1 lab check, done 2026-11-13; Task 5 acceptance).

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces:
  - `struct imap_rule { struct mapi_SPropValue_array props; };` (props owned by the rule; `PidTagRuleId` always present after load)
  - `int imap_rules_decode(TALLOC_CTX *mem_ctx, const char *script, struct imap_rule **rules, uint32_t *count);` — NULL script → 0 rules.
  - `char *imap_rules_encode(TALLOC_CTX *mem_ctx, struct imap_rule *rules, uint32_t count, imap_rules_mailbox_fn mailbox, void *private_data);` — returns the full script text; sets/clears `ST_ERROR` in each rule's `PidTagRuleState`; returns NULL only on OOM. `count == 0` → NULL is not used: caller deletes instead.
